## Obligations added from T12 (2026-10-25) [HUMAN]
- **Always display the approved limitation statement.** The Reporter must always show the approved limitation statement (`docs/requirements.md` line 304 and 6b.9: external URLs are not checked; no dependency or security scanner is run (D9); untracked files are not analyzed (D21); the link kinds in 6b.9 (reference-style links, autolinks, anchor targets, links on lines the edit does not add) are outside the check (D27); consistency is not computed (D28)), whatever the per-item limitation list contains, and must never render the `relative_links` result as passing without it. - The consistency item's detail already starts with "Not Found:" (T11b); do not add a second prefix. Limitation items from T12 have subject `relative_links_limitation`.
- Redact file names and paths in `CheckResult` and `NotFoundItem` fields before output (unredacted structured fields).

## Obligations added from T13 (2026-10-25) [HUMAN]
- **Report the resolved destination.** The Reporter states the resolved destination of the patch whenever it differs from `<cwd>/output/docsync.patch` (output policy B: an `output` that is a symlink, junction or reparse point is refused with exit 11; a different resolved destination can still arise from a link in the working directory or an ancestor). The path is redacted before output. Architecture §2.6 and impl-plan T13 were amended for this (impl-plan §5a, 2026-10-25).
- **Never rely on `redact()` alone to sanitize document text.** `redact()` is a masking helper; some secret formats survive in its output (documented in `docsync/redact.py`: Markdown-formatted names before the 2026-10-25 fix, URL passwords containing an unencoded `@`, unquoted values cut at `,` or `;`, the 64-character suffix bound, and others). Any hunk or document text that `contains_secret` flags must be WITHHELD (the T13 writer does this and writes no patch), not shown in masked form. The Reporter may use `redact()` on paths, file names and short error text, never as the only safeguard for document or hunk text.
- **Surviving-secret caution:** for a flagged line such as `**Password:** FakeBoldSecret1` the T13 audit showed `redact()` can leave the real secret in its output while `contains_secret` is True; report only file and line for withheld hunks (as `WithheldFinding` does).
